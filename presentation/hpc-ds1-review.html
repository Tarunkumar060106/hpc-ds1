02

The idea
04

Like a careful colleague: one change at a time, with a confidence score.

01 · LOOK

Read the job

What it is, its size, this machine, and how the last run went.

→
02 · SUGGEST

Pick one move

"Add a worker", "move to GPU", "use bf16", or "stop, this is good".

→
03 · DECIDE

Sure? Do it.

If confident, it runs automatically. If not, it asks an engineer.

→
04 · CHECK

Measure again

If the move made it slower, undo it and try something else.

Same pattern as Jev: decide → confidence → auto-run or escalate

AI training and backend servers are HPC work too. It learned both.

AI training step

Forward + backward + gradient all-reduce

Backend server

Knows when it doesn't know
18

On a job it has never seen, it no longer guesses. It asks.

240 → 0
confidently wrong automatic moves on never-seen workloads
100%
of never-seen-workload decisions sent to an engineer, with the reason
0
of 286 familiar test decisions flagged: automation on known work is untouched

A familiarity guard checks the machine, the workload, the problem size, and how close the job is to anything it measured. Unfamiliar means escalate, however confident the network is. (Held out of training, server work was decided right only 18% of the time.)
